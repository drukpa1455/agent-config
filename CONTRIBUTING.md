# Contributing

Keep changes focused on a clear benefit. Follow `AGENTS.md` and consult the
owning source and relevant documentation. Explain the missing capability,
failure, or personal preference being addressed; avoid incidental formatting
and unrelated cleanup.

Shared instructions communicate enduring preferences and collaboration boundaries.
Explain the decision a proposed rule should change and where it applies. Prefer
defaults that adapt to project constraints over global implementation mandates.
Skills should provide distinct knowledge, a useful artifact convention, or tool
mechanics, with precise triggers and self-contained references. Preserve user
scope, established authorization, and existing invocation metadata. Keep source
studies revision-bound and make their transfer limits clear.

Installation belongs to `scripts/link`. Checkout updates and worktree cleanup
share locks and preserve unrelated state. Cleanup may delete its verified merged
task branch; these tools never create commits or push code.

Review instructions against concrete requests: the intended decision, whether
the guidance applies, and any unnecessary work or approval it could introduce.
Use real task outcomes to revisit rules; distinguish an editorial judgment from
a measured improvement in agent behavior. Check script changes through isolated
tests of behavior and ownership. Routine prose edits need no evaluation framework
or tests of wording.

Open a pull request when the change is coherent and ready to review. Describe the
result, relevant validation, and any material AI assistance.
